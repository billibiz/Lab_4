# Теоретическая часть

**Основные понятия:**

**Serf** — это инструмент для управления кластером, который использует протокол gossip для обнаружения узлов, обнаружения отказов и оркестрации событий.

**Протокол gossip** — это метод распространения информации в распределенной системе, где узлы периодически обмениваются информацией со случайно выбранными соседями.

**Ключевые параметры:**

- **Gossip Interval** - интервал между раундами gossip-протокола
- **Gossip Fanout** - количество узлов, с которыми каждый узел общается за один раунд
- **Конвергенция** - состояние, когда все узлы в системе имеют согласованное представление о состоянии системы
- **Packet Loss** - процент потери пакетов в сети
- **Node Failures** - процент отказавших узлов в системе

**Гибридный протокол** - комбинированный подход, использующий gossip для обычных узлов и heartbeat для критически важных компонентов системы.

# Анализ результатов и ответы на вопросы

**а) Как изменение Gossip Interval влияет на время конвергенции и использование полосы пропускания?**

Время конвергенции: линейно возрастает с увеличением интервала.
- При Interval=0.1с: 0.75с
- При Interval=2.0с: 15.00с (рост в 20 раз)

Полоса пропускания: обратно пропорциональна интервалу.
- При Interval=0.1с: 26.44 Мбит/с
- При Interval=2.0с: 1.32 Мбит/с (снижение в 20 раз)

То есть уменьшение интервала ускоряет обнаружение, но увеличивает нагрузку на сеть. Оптимум для моего случая — 0.5с.

**б) Какое влияние оказывает увеличение Gossip Fanout на производительность системы?**

Увеличение Fanout ускоряет конвергенцию за счет уменьшения количества раундов распространения, но увеличивает нагрузку на сеть.

**в) Как масштабируется система при увеличении количества узлов?**

Гибридный протокол масштабируется хорошо с логарифмической сложностью для обычных узлов, что позволяет работать с сотнями узлов без серьезного падения производительности.

**г) Каково влияние потери пакетов на время конвергенции?**

Потеря пакетов увеличивает время конвергенции примерно на 15-20 процентов при 5 процентах потерь, но протокол устойчив благодаря избыточности сообщений.

**д) Как процент отказавших узлов влияет на общую производительность системы?**

Увеличение процента отказавших узлов незначительно увеличивает время конвергенции на 5-8 процентов при 5 процентах отказов, но при превышении 20-30 процентов возможны проблемы с согласованием состояния.
