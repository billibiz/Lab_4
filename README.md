# Теоретическая часть

**Основные понятия:**

**Serf** — это инструмент для управления кластером, который использует протокол gossip для обнаружения узлов, обнаружения отказов и оркестрации событий.

**Протокол gossip** — это метод распространения информации в распределенной системе, где узлы периодически обмениваются информацией со случайно выбранными соседями.

**Ключевые параметры:**

- **Gossip Interval** - интервал между раундами gossip-протокола
- **Gossip Fanout** - количество узлов, с которыми каждый узел общается за один раунд
- **Конвергенция** - состояние, когда все узлы в системе имеют согласованное представление о состоянии системы
- **Packet Loss** - процент потери пакетов в сети
- **Node Failures** - процент отказавших узлов в системе

**Гибридный протокол** - комбинированный подход, использующий gossip для обычных узлов и heartbeat для критически важных компонентов системы.

# Анализ результатов и ответы на вопросы

**а) Как изменение Gossip Interval влияет на время конвергенции и использование полосы пропускания?**

Время конвергенции: линейно возрастает с увеличением интервала.
- При Interval=0.1с: 0.75с
- При Interval=2.0с: 15.00с (рост в 20 раз)

Полоса пропускания: обратно пропорциональна интервалу.
- При Interval=0.1с: 26.44 Мбит/с
- При Interval=2.0с: 1.32 Мбит/с (снижение в 20 раз)

ТО есть уменьшение интервала ускоряет обнаружение, но увеличивает нагрузку на сеть. Оптимум для моего случая — 0.5с.

**б) Какое влияние оказывает увеличение Gossip Fanout на производительность системы?**

Параметр Gossip Fanout определяет степень связности сети и напрямую влияет на скорость распространения информации. Исследование показывает, что увеличение Fanout с 1 до 3 обеспечивает сокращение времени конвергенции на 25-30% благодаря уменьшению количества шагов распространения сообщений. Каждый дополнительный канал связи сокращает среднее число раундов, необходимых для достижения согласованного состояния во всей системе.

Однако этот выигрыш в производительности имеет нелинейный характер. После достижения Fanout=4-5 дальнейшее увеличение параметра дает незначительное улучшение времени конвергенции при продолжающемся равномерном росте нагрузки на сеть (20-25% на каждое дополнительное соединение). Это явление объясняется законом убывающей отдачи и наличием избыточных путей распространения информации.

**в) Как масштабируется система при увеличении количества узлов?**

Изучение масштабируемости системы выявило логарифмическую зависимость времени конвергенции от количества узлов в кластере. Гибридный протокол показывает сложность O(log N + K×N), где N - общее количество узлов, K - доля критических узлов. Такая характеристика обеспечивает приемлемую производительность даже в крупных кластерах, насчитывающих несколько сотен узлов.

Сравнительный анализ с альтернативными подходами демонстрирует преимущество гибридного протокола перед решениями, основанными только на heartbeat-механизмах, которые обладают квадратичной сложностью O(N²), что делает их неприменимыми в крупномасштабных системах. При этом гибридный подход сохраняет возможность быстрого обнаружения отказов критических компонентов, что недостижимо в реализациях, использующих только gossip-протокол.

**г) Каково влияние потери пакетов на время конвергенции?**

Эксперименты с различными уровнями потери пакетов показали устойчивость гибридного протокола к сетевым проблемам. При 5% потерь пакетов, характерных для большинства промышленных сред, время конвергенции увеличивается на 15-20%. Этот эффект объясняется необходимостью дополнительных раундов обмена для компенсации утраченных сообщений.

Математическая модель, описывающая данную зависимость, может быть представлена как: T_фактическое = T_идеальное × (1 + α×PL), где PL - вероятность потери пакета, α - коэффициент, зависящий от структуры сети (в нашем случае α ≈ 3-4). Избыточность gossip-протокола обеспечивает надежное распространение информации даже в условиях неидеальной сети.

**д) Как процент отказавших узлов влияет на общую производительность системы?**

Анализ влияния отказа узлов на производительность системы показал, что при 5% отказах (параметр варианта 20) снижение производительности минимально - время конвергенции увеличивается на 5-8%. Это обусловлено уменьшением количества активных участников процесса обмена и соответствующим снижением сетевой нагрузки.

Критическим пределом для системы является уровень отказов 20-30%, при котором начинают возникать проблемы с достижением согласованного состояния из-за разделения сети на изолированные группы. Однако даже в таких условиях гибридный протокол сохраняет работоспособность для критических узлов благодаря heartbeat-механизмам, что является существенным преимуществом по сравнению с решениями, использующими только gossip-протокол.

Устойчивость к отказам демонстрирует принципиальное преимущество распределенных систем перед централизованными архитектурами, где отказ единственного координатора приводит к полной неработоспособности системы.
